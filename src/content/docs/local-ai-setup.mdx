<DocSection title="What You Need">

A Mac with Apple Silicon, or a Linux PC with a GPU. Memory decides which model you can run: a 4B model needs about 4 GB free, the 26B and 35B models need 20 to 24 GB free. Disk: 3 GB for the small model, up to 22 GB for a large one.

Everything runs on your machine. No account, no API key, and nothing is sent anywhere.

</DocSection>

<DocSection title="Install the Editor and a Model Server">

Install the editor from the [macOS DMG](/download.html), or build it from source. Either way, the model runs in a second program, `llama-server` from [llama.cpp](https://github.com/ggml-org/llama.cpp), which 0.1.0-alpha.1 does not include. On a Mac, Homebrew is the simplest route; on Linux, unpack a [prebuilt release](https://github.com/ggml-org/llama.cpp/releases) and point the editor at it.

<CommandList commands={[
  "brew install llama.cpp",
  "cargo install --git https://github.com/fontgarden/runebender",
  "export RUNEBENDER_LLAMA_SERVER=/path/to/llama-server",
]} />

The second command is the source build, for those not using the DMG. The third is for a server that is not on your `PATH`. The editor looks beside its own binary, then at `RUNEBENDER_LLAMA_SERVER`, then on `PATH` and in Homebrew's folders, so an app opened from the Finder finds a Homebrew install without any setting.

Without `llama-server`, the editor runs and edits fonts as usual. The Chat tab lists your models but a question ends with the note "Neither llama-server nor font-ml found; install one or set RUNEBENDER_LLAMA_SERVER" in the status line.

<Callout>
  Homebrew's `llama.cpp` and `whisper.cpp` share one library. Upgrade them together, `brew upgrade llama.cpp whisper.cpp`, never one alone, or the other stops loading models.
</Callout>

</DocSection>

<DocSection title="Get a Chat Model">

A chat model is one GGUF file in its own folder under `~/Runebender/models`. The folder name is the name you see in the editor. Download a file from Hugging Face, rename it `model.gguf`, and put it in place:

<CommandList commands={[
  "mkdir -p ~/Runebender/models/qwen3.5-4b",
  "mv ~/Downloads/Qwen3.5-4B-UD-Q4_K_XL.gguf ~/Runebender/models/qwen3.5-4b/model.gguf",
]} />

| Model | File | For |
| --- | --- | --- |
| [Qwen3.6-35B-A3B](https://huggingface.co/unsloth/Qwen3.6-35B-A3B-GGUF) | `UD-Q4_K_XL`, 22 GB | The daily model on a 48 GB Mac: reliable tool use, about 40 words a second |
| [Gemma 4 26B-A4B](https://huggingface.co/unsloth/gemma-4-26B-A4B-it-GGUF) | `UD-Q4_K_XL`, 17 GB | A second opinion, slightly faster |
| [Qwen3.5-4B](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF) | `UD-Q4_K_XL`, 3 GB | Laptops with 8 to 16 GB; weaker at multi-step edits |

Two optional files go beside the model. `model.json` sets the server's defaults for that model, such as `{"thinking": false, "temperature": 0.7}`; the keys are listed in [Local models](/docs/local-models.html). An `mmproj*.gguf` file from the same Hugging Face repository is the vision projector: with it, the model can look at proof pictures.

</DocSection>

<DocSection title="Ask About Your Font">

<CommandList commands={[
  "runebender path/to/MyFont.designspace",
]} />

Open the **Chat** tab in the left rail and pick the model with the chip under the text field. The first question loads the model, which takes about fifteen seconds; after that answers start at once. Begin with a specific request, such as "Inspect the selected glyph and explain its spacing."

For a change, ask for a proposal: "Make the zero 64 units wider." The model reads the glyph and proposes an edit. Open **Proof** with the fourth button at the bottom left of the editor to see the proposal beside the current drawing, in Compare, Toggle, Waterfall or Text. Apply it from there if you agree, or return to the canvas and draw it your way. Nothing is applied or saved until you do it.

A vision model can be asked to look: "Then ask for the proof images and tell me what changed." It is good at closed questions, which drawing is wider or which side moved, and poor at judging whether a drawing is good. Treat its assessment as feedback.

</DocSection>

<DocSection title="One Server for Several Programs">

A coding agent such as Pi or Hermes can use the same models. Run one `llama-server` in router mode over the models folder and every program shares it; a model is in memory once.

<CommandList commands={[
  "llama-server --models-dir ~/Runebender/models --host 127.0.0.1 --port 8080",
]} />

The router lists every folder with a `model.gguf` and loads one the first time a program asks for it by name. When this server is running on port 8080, the editor's Chat uses it instead of starting its own. A `presets.ini` in the models folder gives each model its settings, one section per folder name; see [Local models](/docs/local-models.html). The server answers on this machine only and has no API key, so do not change the host.

</DocSection>

<DocSection title="Optional Pieces">

- **Voice input.** `brew install whisper.cpp`, then put a [whisper.cpp model](https://huggingface.co/ggerganov/whisper.cpp) as `~/Runebender/models/whisper-small/model.bin`. The microphone button appears in Chat.
- **Agents.** External agents connect to the live editor through `runebender mcp --live`; see [MCP and the live editor](/docs/mcp.html). The agent's own setup decides whether its model is local or remote.
- **Review pictures for agents.** The `review_proof` tool renders through [Designbot](https://github.com/eliheuer/designbot), installed with `cargo install --git https://github.com/eliheuer/designbot designbot-cli`.
- **Drawing models.** Local AI Shapes and Bolden use `font-ml` and its trained models, which are a separate install and a separate kind of model. The [runebender-local-ai-demo](https://github.com/eliheuer/runebender-local-ai-demo) repository walks through them.

</DocSection>

<DocSection title="Where Models Live">

The editor reads `~/Runebender/models`, a visible folder you can open in Finder. `RUNEBENDER_MODELS` overrides it for one run, and `~/.runebender/model_paths` or `RUNEBENDER_MODEL_PATHS` lists extra folders, one per line. The older `~/.runebender/models` is still read.

| Kind | Where | Files |
| --- | --- | --- |
| Chat model | `~/Runebender/models/<name>/` | `model.gguf`, optional `model.json`, optional `mmproj*.gguf` |
| Speech model | `~/Runebender/models/whisper-<size>/` | `model.bin` |
| Shapes model | `~/Runebender/models/shapes/` or `MyFont.models/shapes/` | `config.json`, `weights.safetensors`, `vocab.txt`, `manifest.json` |
| Bolden model | `~/Runebender/models/bolden/` or `MyFont.models/` | `config.json`, `weights.safetensors`, `vocab.txt` |

A chat model does not draw shapes, and a shapes model does not talk.

</DocSection>

<DocSection title="Recover from Common Failures">

- **No model in the Chat picker:** the file must be named with a `.gguf` extension inside its own folder directly under `~/Runebender/models`. Check `RUNEBENDER_MODELS` if you set it.
- **"Neither llama-server nor font-ml found":** install `llama-server`, or set `RUNEBENDER_LLAMA_SERVER` to its path, then ask again.
- **The model fails to load after a Homebrew upgrade:** `brew upgrade llama.cpp whisper.cpp` together, then try again.
- **Port 8080 is taken:** another program holds it. Stop that program, or let the editor start its own private server by leaving port 8080 alone.
- **The first answer is slow:** the model is loading. The second answer is fast.
- **A proposal changes nothing, or the model loops:** small models misname tool arguments. Ask again in plainer words, or pick a larger model.

Continue with [Local models](/docs/local-models.html) for what the editor does with each model, and [Type design with agents](/docs/type-design.html) for the working method.

</DocSection>
