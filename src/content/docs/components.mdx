<DocSection title="Components">

A component places another glyph inside this one. Edit the base glyph
and every glyph using it follows.

Add one from the canvas context menu and type the base glyph name.
Select and drag a component with the select tool, and double-click it
to open the glyph it points at. Delete removes it.

<table>
  <caption>Component commands</caption>
  <tbody>
    <tr><th>Decompose Components</th><td><code>Cmd+Shift+D</code>. Replaces every component with its outlines.</td></tr>
    <tr><th>Decompose One</th><td>Context menu. Only the component under the pointer.</td></tr>
    <tr><th>Lock / Unlock</th><td>Context menu, or the toggle in the Coordinates panel.</td></tr>
  </tbody>
</table>

The Related section of the right panel lists the glyphs this one uses
as components and every composite that uses it, one click away each.

</DocSection>

<DocSection title="Anchors and Auto-Alignment">

An anchor is a named point that says where a mark attaches. Give the
base glyph an anchor, give the mark a matching one, and the mark
places itself.

Composites align live. Move the anchor on a base glyph and every
accented glyph built from it follows immediately. A component locked
to an anchor refuses to be dragged, because its position comes from
the anchor rather than from you. Use the Lock and Free toggle in the
Coordinates panel to override that.

A component added from the context menu arrives anchor-locked, so
marks snap to their anchor without extra work.

</DocSection>

<DocSection title="Editing Anchors">

Add and delete anchors from the canvas context menu. Select one with
the select tool and drag it, or set exact coordinates in the
Coordinates panel: with an anchor selected, the X and Y fields address
the anchor itself. Its name is a field in the same panel.

Anchor names drive generated feature code. Entry and exit anchors
produce cursive attachment, anchor families produce mark and mark-to-
mark positioning, and `caret_1`, `caret_2` and so on produce ligature
caret positions. See [Feature Code](/docs/features.html).

</DocSection>

<DocSection title="Smart Components">

A smart component carries its own axes, so one part glyph can hold a
range of shapes. A single serif component can be short at one end of
its range and long at the other, and each placement picks a value.

To make one, use Smart Axis on a part glyph and give it an axis as
`Width,0,100`. That writes the glyphsLib `smartComponentAxes` entry,
marks the default drawing as the bottom pole, and seeds a `.top` layer
as the other pole. Edit the poles through the swap arrows.

Place the part in a glyph and set its value in the Coordinates panel.
Interpolation across several axes uses the corner-delta model
described in
[Masters and Interpolation](/docs/masters.html).

<Callout>
  Smart components use the glyphsLib keys, so a source that came out
  of Glyphs keeps working and a source that leaves Runebender takes
  them along.
</Callout>

</DocSection>

<DocSection title="Corner Components">

A corner component reshapes a node rather than adding a shape: a
chamfer, a flare, a spur applied consistently everywhere it belongs.

Apply one from the context menu at a node, naming it `chamfer` or
`_corner.chamfer`. It is applied in every master, because all masters
must keep the same structure to interpolate.

</DocSection>

<DocSection title="Joining Scripts">

Glyph, Check Joining is for cursive scripts. For every positional
form, it measures the connecting stroke's band at the joining edges,
where initial and medial join at x = 0 and medial and final at the
advance, then finds the font's common band and selects every form that
misses it.

It measures the joining line rather than asking you to eyeball it.
See [Text and Shaping](/docs/text.html).

</DocSection>
