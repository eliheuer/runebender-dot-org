<DocSection title="Source">

[runebender-xilem](https://github.com/eliheuer/runebender-xilem) contains the
application and its font library in one Cargo workspace. Start with its
`AGENTS.md` and read `DESIGN.md` before changing the interface.

</DocSection>

<DocSection title="Build and Run">

```sh
git clone https://github.com/eliheuer/runebender-xilem
cd runebender-xilem
cargo run --release -- path/to/Font.designspace
```

The repository pins its Rust toolchain and upstream Xilem revision.
Use the platform prerequisites in its README.

</DocSection>

<DocSection title="Checks">

From the workspace root:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets
cargo doc --workspace --no-deps
cargo test --workspace -- --test-threads=1
cargo build --workspace --release
```

Font-based tests use Virtua Grotesk. Set `RUNEBENDER_TEST_FONTS` to its
`sources` directory. CI runs on Linux and macOS with warnings denied.
Dependency changes also need the repository's supply-chain checks.

</DocSection>

<DocSection title="Where Things Live">

The interface lives under `src/`. Font operations live in the workspace's
library under `crates/`, where they can be tested without opening a window.
Both are changed in the same checkout. See [Code Layout](/docs/code-layout.html).

Use Xilem and Masonry controls, the existing theme tokens, and the editor's
command methods. Keep reusable font operations independent of UI state.

</DocSection>

<DocSection title="The Browser Build">

There is no working browser build of runebender-xilem yet. The first milestone
is running the existing Xilem/Masonry interface in WebAssembly, then opening a
sample font, editing a glyph, and exporting the result.

The pinned UI framework currently enables a desktop-only async runtime feature
that fails on `wasm32-unknown-unknown`. Browser startup, rendering, file access,
clipboard, and text input need separate verification. A native build or a
headless screenshot does not establish browser support.

</DocSection>
