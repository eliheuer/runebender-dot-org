<DocSection title="Build an Accented Glyph">

1. Draw the base letter and the mark as separate glyphs.
2. Put an anchor on the base where the mark belongs, and a matching
   one on the mark.
3. Open the accented glyph. In the Shapes panel of the left rail, type
   each name in the Base glyph field and press Add.
4. The mark places itself from the anchors, and stays put when you
   edit the base.
5. Run Generate in the Features section of the grid view to write the
   `mark` feature from those anchors.

See [Components and Anchors](/docs/components.html) and
[Feature Code](/docs/features.html).

</DocSection>

<DocSection title="Draw From a Skeleton">

1. With the pen tool, draw open paths down the middle of the strokes.
2. Select them, or select nothing to take the whole glyph.
3. In the Path Operations section, type a weight in Stroke width and
   press Enter.
4. Clean up with Remove Overlap and Correct Path Direction.

Copy the skeleton to a named glyph layer first, with Copy to layer in
the Layers section. Then you can expand it again at a different weight
instead of redrawing.

See [Paths and Filters](/docs/paths.html).

</DocSection>

<DocSection title="Add a Weight">

1. Open the designspace. Set the axis sliders to the new weight.
2. Type a name in Source name and press Add source in the Masters
   section. Runebender adds an interpolated source, and Save writes
   its new UFO.
3. Draw the new master, then use the axis sliders to check what falls
   between.
4. Use the Compare section to find glyphs that no longer interpolate.

See [Masters and Interpolation](/docs/masters.html) and
[Checking a Font](/docs/checking.html).

</DocSection>

<DocSection title="Space and Kern a Font">

1. Set widths and sidebearings on the control characters first, with
   the Width, LSB and RSB fields in the Glyph section.
2. If the source has metric keys, run Glyph → Update Metrics to apply
   every key.
3. Put glyphs that kern alike into groups, so one value covers many
   pairs.
4. Set pairs with the First, Second and Value fields in the Kerning
   section of the grid view.
5. Check the result in real words with the text tool.

See [Spacing and Kerning](/docs/spacing.html).

</DocSection>

<DocSection title="Start an Arabic Font">

1. Name the positional forms by convention: `beh.init`, `beh.medi`,
   `beh.fina`, with `beh` as the isolated form.
2. Put entry and exit anchors on the joining edges.
3. Run Generate in the Features section. It writes `init`, `medi`,
   `fina`, and `curs` from those names and anchors.
4. Press Apply, then type words with the text tool and read them.
5. Run Glyph → Check Joining. It selects every form whose connecting
   stroke misses the font's common band.
6. When a word comes out wrong, use the Shaping section to turn
   features off one at a time, or to change the script and language.

See [Text and Shaping](/docs/text.html).

</DocSection>

<DocSection title="Trace a Drawing">

1. Glyph → Place Image… puts a bitmap behind the glyph.
2. Glyph → Trace Image… converts it to contours. It is undoable.
3. Tidy the result: Optimize, then Add Extremes, then Correct Path
   Direction.

For a cleaner result, trace to get the shape and then redraw over it
with the pen tool, using the image as a reference rather than as the
outline.

See [Glyphs](/docs/glyphs.html).

</DocSection>

<DocSection title="Make a Variable Font">

1. Draw the masters and keep them compatible as you go.
2. Use the Compare section and fix what it reports.
3. Run File → Export.

<Callout>
  Export compiles the open document with fontc inside Runebender,
  including edits you have not saved. It writes
  <code>exports/&lt;name&gt;.ttf</code> beside the source. See
  <a href="/docs/exporting.html">Exporting</a>.
</Callout>

</DocSection>

<DocSection title="Work on a Font From a Terminal">

Runebender reloads files changed on disk, so a script and the editor
can share a font.

1. Keep the editor open on the designspace.
2. Run your script over the UFO.
3. The editor picks up the change.

Keep the source in version control, so a script that goes wrong is one
`git checkout` away from being undone.

</DocSection>
