<DocSection title="Glyphs Files">

Opening a `.glyphs` file or `.glyphspackage` folder converts it to UFO/Designspace files in a new sibling directory.
Save writes the working copy and merges supported changes back into the original source.
The first write-back keeps a backup named `<name> (before Runebender).<ext>`.
Save As writes UFO/Designspace files instead.

Outlines, components, anchors, widths, Unicode values and basic kerning are imported.
This is basic alpha support: features, hints, smart-component behavior and some layers are not read into the working copy.
Edited layers can lose unsupported data, including hints and node metadata.
Font-info and feature edits are not written back; new masters cannot be written back either.
Glyphs 2 files are written back as Glyphs 3.
Written files have not yet been checked by reopening them in Glyphs itself.
Work on copies of important sources.

</DocSection>

<DocSection title="Fontra Folders">

The native editor opens `.fontra` folders, converts them to UFO/Designspace working copies, and merges supported edits back on Save.
The backup and Save As behavior is the same as for Glyphs sources.
It reads continuous axes, full sources, outlines, components, anchors, advance widths, basic kerning and feature text.

Support is incomplete: sparse sources, glyph axes and variable-component locations are not editable; discrete axes open only at their default value.
Cross-axis mappings are ignored, and most font-info or source-structure changes are not written back.
The editor watches the converted working copy rather than changes made to the original by another app.
Written folders have not yet been checked by reopening them in Fontra itself.
These Glyphs and Fontra workflows have not been validated in the browser editor.

</DocSection>

<DocSection title="Babelfont Packages">

A `.babelfont` package here means the Python Babelfont directory format: `info.json`, `names.json`, `glyphs.json`, and per-glyph `.nfsglyph` files.
It is not Rust Babelfont JSON, which is unsupported.
No Python installation is needed to import it.

The native project importer supports multiple masters, continuous axes, instances and extra layers within its checked conversion rules.
It imports outlines, components, anchors, widths, Unicode values, names, metrics, kerning and self-contained feature text.
Unsupported fields are rejected rather than silently discarded; external feature includes are not supported.
Saving writes UFO/Designspace sources and never rewrites the original `.babelfont` package.

</DocSection>

<DocSection title="Compiled Fonts">

A `.ttf` or `.otf` opens as an editable UFO built in memory from the
binary. It is a way to look inside a font, take a shape out of one, or
start from something that only exists compiled.

Saving writes that UFO next to the binary. It never writes over the
binary, and exporting compiles from the UFO rather than touching the
original file.

</DocSection>

<DocSection title="A New Font">

The native editor starts in its normal glyph grid with a new, untitled font.
<code>Cmd+N</code> creates the same template: Google Fonts metrics and 324 empty Latin Core glyph slots.
The font stays in memory until you save it.

Use File → Open to replace the starter with an existing font.
An untouched starter needs no save prompt; after an edit, opening another font or quitting offers Save, Discard, or Cancel.
The first Save asks for a destination folder and writes `Untitled.ufo` there.
Choose an empty folder if it already contains a file with that name; existing destinations are not overwritten.
Cancelling the folder picker keeps the font and its edits open.
Later saves write to the chosen location.

Starting from a real glyph set rather than an empty file means the
grid, the language coverage rows, and the search all do something from
the first minute.

</DocSection>

The footer shows the path of the open font and Saved or Not saved,
so you can tell whether what is on screen is on disk.

<Callout>
  Runebender writes your sources in place. Keep them in version
  control. A UFO is a directory of small files, so a day's drawing
  reads as a reviewable diff.
</Callout>

</DocSection>

<DocSection title="Changes From Outside">

Runebender watches the files it has open. Edit a UFO with another
tool, run a script over it, or check out a different branch, and the
editor reloads.

That makes it reasonable to keep the editor open while working on the
same font from a terminal.

</DocSection>
