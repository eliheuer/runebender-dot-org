<DocSection title="Sources">

Runebender opens `.designspace` files, `.ufo` directories, and folders
that hold them. It saves in the same format, in place.

UFO is a directory of files, so a font source works with version
control. Commit your sources and you can see, review, and undo a day's
drawing the way you would any other change.

<Callout>
  Runebender writes to your files. Keep them in version control and
  work on copies while the editor is alpha.
</Callout>

</DocSection>

<DocSection title="Standard Data">

<table>
  <caption>Standard UFO data</caption>
  <tbody>
    <tr><th>Outlines</th><td>GLIF contours, points, and components.</td></tr>
    <tr><th>Anchors</th><td>Standard GLIF anchors.</td></tr>
    <tr><th>Kerning</th><td><code>kerning.plist</code> and <code>groups.plist</code>, per master.</td></tr>
    <tr><th><code>public.kern</code></th><td>Group names follow the standard prefixes.</td></tr>
    <tr><th><code>public.background</code></th><td>The background layer, saved with the font.</td></tr>
    <tr><th><code>public.postscriptNames</code></th><td>Production names, used on export.</td></tr>
    <tr><th>Features</th><td><code>features.fea</code>, one file per master, holding prefixes, classes, and features.</td></tr>
    <tr><th>Layers</th><td>Backup and intermediate layers are ordinary UFO layers. Intermediate layers also add a sparse designspace source.</td></tr>
    <tr><th>Designspace</th><td>Axes, sources, instances, <code>avar</code> mappings, and substitution rules for shape switches.</td></tr>
    <tr><th><code>com.github.googlei18n.ufo2ft.colorPalettes</code></th><td>The CPAL palette for colour fonts.</td></tr>
  </tbody>
</table>

</DocSection>

<DocSection title="Glyphs Compatibility">

Sources that came out of Glyphs keep their smart component data.
Runebender reads and writes the glyphsLib keys rather than inventing
its own.

<table>
  <caption>glyphsLib keys</caption>
  <tbody>
    <tr><th><code>com.schriftgestaltung.Glyphs.smartComponentAxes</code></th><td>The axes a smart component carries.</td></tr>
    <tr><th><code>com.schriftgestaltung.Glyphs.componentsSmartComponentValues</code></th><td>Where a placed component sits in those axes.</td></tr>
    <tr><th><code>com.schriftgestaltung.Glyphs.glyph.leftMetricsKey</code></th><td>Metric keys, left and right. See <a href="/docs/spacing.html">Spacing and Kerning</a>.</td></tr>
  </tbody>
</table>

</DocSection>

<DocSection title="Runebender Keys">

Anything Runebender needs that UFO does not define lives under its own
namespace. Another editor ignores these keys, and the rest of the
source still reads correctly.

<table>
  <caption>com.runebender keys</caption>
  <tbody>
    <tr><th><code>savedFilters</code></th><td>Filters saved in the left panel.</td></tr>
    <tr><th><code>annotations</code></th><td>Notes left on a glyph.</td></tr>
    <tr><th><code>masks</code></th><td>Intermediate mask layers.</td></tr>
    <tr><th><code>hoiIntermediate</code></th><td>Higher-order interpolation intermediates.</td></tr>
    <tr><th><code>partSelection</code></th><td>Which part of a smart component is in use.</td></tr>
  </tbody>
</table>

</DocSection>

<DocSection title="Hyperbeziers">

A hyperbezier contour is defined by its on-curve points, with the
control points solved rather than placed. Runebender marks these
contours in GLIF with `identifier="hyperbezier"`.

An editor that does not know the identifier reads the points as
ordinary curve points, so the file stays valid. Use Path, Hyperbezier
to Cubic before handing a source to a tool that needs plain cubics.

</DocSection>

<DocSection title="What Survives a Round Trip">

Runebender aims to write files another tool can read. Standard data
stays standard, Glyphs-compatible data uses the glyphsLib keys rather
than a private spelling, and anything genuinely new sits under
`com.runebender` where another editor will ignore it and leave the
rest of the source intact.

Two things to know before handing a source on:

1. Hyperbezier contours read as ordinary curves elsewhere. Convert
   them if the receiving tool will re-save the file.
2. Masks are a Runebender idea. Run Glyph, Bake Masks so the
   subtraction is real in the outlines.

</DocSection>
